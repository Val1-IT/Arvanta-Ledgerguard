Deterministic policy for agents that touch the ledger.

LedgerGuard is verification infrastructure for AI agents doing financial and ERP actions. Agents may investigate and propose a repair. They do not receive mutation authority just because a model emitted a tool call. Policy is ordinary code: ALLOW, DENY, or REQUIRE_APPROVAL. A human approves an exact plan version. Execution is verified against the system of record, then an audit receipt is issued.

What this page demonstrates

Policy checks

The six rules in @ledgerguard/policy run in this browser: evidence, verification, financial impact, capability, exact-version approval, and idempotency. The most severe outcome wins.

Human approval

REQUIRE_APPROVAL stops execution until a human operator accepts the exact plan version. An AI agent cannot approve. When the assistant requests approval, this browser asks you to confirm first.

Audit receipts

Every evaluation and committed execution writes a hashed receipt you can inspect. Replaying a completed idempotency key is DENY: DUPLICATE_EXECUTION. Nothing is invented; decisions come from the engine.

What this site cannot do

    

      
It cannot write to a live ERP or production database, collect payment, run a publisher-funded LLM, or expose a public MCP facade. An AI agent cannot approve a plan. Other agentic websites can fetch the published agent-manifest.json and network file once this site is hosted with CORS; this static page does not itself call theirs.

    

  

  

    
Ask LedgerGuard

    
The assistant can read this page's ledger, evaluate a plan, request your approval, execute a verified repair, and fetch audit receipts. It uses only the site's own functions and the facts they return.
